# 읽기 화면 전면 개편 — 앱 셸 · 타이포그래피 · Mermaid 다이어그램

날짜: 2026-09-06
브랜치: `feat/reading-view-overhaul`

## 배경 — 사용자가 보고한 세 가지

1. `/graph` 화면에서 **로그인 버튼이 다른 컴포넌트를 가린다.**
2. **다이어그램을 Mermaid로 바꾸고 싶다.**
3. **가독성을 크게 개선하고 싶다.** 참고 앱 = Bear. "지금은 답답하다(cramped)."
   레이아웃/데이터를 유지할 필요 없음. 완전히 새로 만들어도 좋음.

## 진단

### #1은 z-index 문제가 아니다 — 앱 셸이 없다

`SearchBar`(좌상단) · `AuthButton`(우상단 `right:62px`) · `ThemeSwitcher`(우상단
`right:16px`) · `ViewToggle`(하단 중앙) 네 개가 각자 `position: fixed`로 콘텐츠
**위에** 떠 있다. 그래프 캔버스는 `100vw × 100vh`를 전부 차지하고, 여백을
예약해 주는 주체가 없다.

- 결과 1: `fitView`가 배치한 우상단 노드가 로그인 pill 뒤로 들어간다. 스크린샷의
  보라색 테두리 사각형은 `dsa` 도메인(`#8b5cf6`)의 `.km-concept` 노드다.
  가려지는 것에 그치지 않고 **클릭이 막힌다**.
- 결과 2: 하단 `ViewToggle`이 읽기 화면 본문 마지막 줄 위에 얹힌다.
- 결과 3: 모든 뷰가 `position:fixed; inset:0; padding-top:60px`으로 상단 바
  높이를 **각자 추측**한다. 상단 바가 바뀌면 7개 뷰가 같이 깨진다.

→ 근본 원인이 하나이므로 고치는 지점도 하나여야 한다: **진짜 레이아웃 프레임**.

### #2 ASCII 다이어그램은 이미 깨져 있다

노트 20개 / 펜스 블록 302개 / 그중 **ASCII 다이어그램 107개**.

한글은 전각(2셀), 라틴은 반각(1셀)이다. 박스를 반각 기준으로 그렸기 때문에
**한글이 섞인 모든 박스는 열 정렬이 무너진다**. 미관이 아니라 기능 결함이다.
(사용자 스크린샷의 `레지스터 |` 열 어긋남이 그 증거.)

성격별 분류와 처리 방침:

| 유형 | 개수 | 처리 |
|------|------|------|
| 흐름 · 상태 · 시퀀스 | ~55 | Mermaid `flowchart` / `stateDiagram-v2` / `sequenceDiagram` |
| 공간 · 포함 관계 (Heap `Eden\|S0\|S1`, TLAB, Process A/B) | ~25 | Mermaid 중첩 `subgraph` |
| 계층 · 바이트 레이아웃 (메모리 계층 피라미드, JWT 3분할) | ~10 | **Mermaid로 강제하지 않는다.** 전용 `figure` 컴포넌트 |
| 실은 다이어그램이 아님 (`jps`/`jstat`/`jmap` 명령 목록) | ~15 | ` ```bash ` |
| 실은 표 (`\|`+`-` 오탐) | ~2 | 마크다운 표 |

`mermaid` 패키지는 gzip ~700KB다. **mermaid 펜스가 있을 때만 dynamic import**하고,
활성 테마 6종의 토큰을 `themeVariables`로 주입한다.

### #3 가독성 — 측정된 결함

```
현재 (2000px 화면)          Bear
─────────────────────       ─────────────────────
본문 폭 ~1650px             본문 폭 ~620px
= 한글 90자/줄              = 한글 ~36자/줄
```

1. **측정폭(measure) 무제한.** `.docs-content`는 `flex:1 1 auto`, `.np-note`에
   `max-width` 없음. 한글 적정 측정폭 40~45자의 2배가 넘는다. 단일 최대 손해.
2. **제목이 본문보다 작다.** 루트 본문 18px, `.np-note h1,h2 { 17px }`,
   `h3 { 15px }`, 섹션 제목 19px. 위계가 뒤집혀 스캔이 불가능하다.
3. **문단 간격 0.** `index.css`의 전역 `p { margin: 0 }`이 노트 본문까지 적용된다
   (`.np-note p`는 `color`만 지정). 문단이 서로 붙는다.
4. **본문 시작 전 크롬 5단.** 제목 → 요약 → 키워드 → 연결된 개념 칩 →
   섹션 칩 클라우드(`.np-outline`, 20개가 `flex-wrap`으로 2줄). 첫 글자까지 ~250px.
5. **표·코드가 본문보다 작다**(둘 다 13px) + 셀마다 테두리 → 밀도만 높다.
6. **하단 `ViewToggle`이 본문 위에 얹힌다** (#1과 동일 원인).
7. **트리 사이드바 13px 균일 행** — 도메인/개념/하위개념이 거의 같은 무게라
   리듬이 없다.

## 설계

### A. 앱 셸 — `position: fixed` 위젯을 실제 그리드로 교체

```
┌──┬────────────────────────────────────────────────────┐
│⌂ │ 개념 검색                            [로그인][테마] │ 상단 바 52px
│🗺│────────────────────────────────────────────────────│
│☰ ├──────────┬───────────────────────┬─────────────────┤
│🧠│ 트리      │  문서 (max 40em)       │ 목차 레일        │
│🛣│ 280px    │                       │ 220px           │
│💼│          │                       │                 │
│📖│          │                       │                 │
└──┴──────────┴───────────────────────┴─────────────────┘
 56px  ← 뷰 전환 아이콘 레일 (기존 하단 pill 대체)
```

- `.app { display: grid; grid-template-columns: 56px 1fr; grid-template-rows: 52px 1fr; height: 100dvh }`
- 뷰 전환 7개(홈/지도/목록/퀴즈/코스/내 이력/가이드)는 **좌측 아이콘 레일**로
  이동한다. 상단 바에 7개를 검색·인증·테마와 함께 넣으면 1280px에서 붐빈다.
  아이콘 레일은 수직이라 항목이 늘어도 안전하다.
- 상단 바가 `SearchBar` · `AuthButton` · `ThemeSwitcher`를 **자식으로** 소유한다.
  세 컴포넌트에서 `position: fixed`를 제거한다.
- 각 뷰는 `position:fixed; inset:0; padding-top:60px` → `height:100%; min-height:0`.
  상단 바 높이를 추측하는 코드가 사라진다.
- 그래프 캔버스는 `100vw/100vh` → `100%/100%`. **#1이 구조적으로 재발 불가능**해진다.

반응형:
- `< 1200px` 목차 레일 숨김 → 문서 상단의 접이식 목차로 대체
- `< 900px` 트리는 드로어(`☰`)
- `< 768px` 좌측 레일 → 하단 탭 바. **떠 있는 오버레이가 아니라 그리드 행**이므로
  본문을 가리지 않는다.

### B. 타이포그래피 시스템 — `src/styles/prose.css`

`.prose` 하나로 노트 본문 · 퀴즈/드릴/리뷰 답안을 모두 커버한다. 렌더되는 모든
요소를 명시적으로 지정해 전역 `index.css` 규칙(`p{margin:0}`,
`h1{56px}`, `code{display:inline-flex}`)의 영향을 차단한다.

본문 기준 17px / line-height 1.8, 측정폭 40em(≈680px):

| 요소 | 크기 | 무게 | 여백 |
|------|------|------|------|
| 문서 제목 h1 | 32px | 700 | ls −0.02em, lh 1.22 |
| 리드(요약) | 18px | 400 | dim, lh 1.65 |
| h2 | 23px | 650 | margin-top 44px |
| h3 | 19px | 650 | margin-top 32px |
| h4 | 17px | 700 | margin-top 24px, dim |
| p | 17px | 400 | lh 1.8, margin-bottom 20px |
| li | 17px | 400 | lh 1.8, li 간 8px |
| 표 | 15.5px | — | 테두리 없음, 헤더 규칙 + 행 hairline |
| pre | 14px | — | lh 1.65 |
| inline code | 0.9em | — | — |

**넓은 요소 브레이크아웃** — 표 · 코드 · 다이어그램은 40em보다 넓어야 한다.
CSS 그리드 3열 트릭으로 처리한다:

```css
.prose { display: grid; grid-template-columns: 1fr min(40em, 100%) 1fr; }
.prose > *          { grid-column: 2; }
.prose > .prose-wide { grid-column: 1 / -1; max-width: 56em; justify-self: center; }
```

### C. 읽기 화면 재구성

- 문서 상단에서 **키워드 · 연결된 개념 · 읽음 표시**를 걷어내 목차 레일 하단으로
  옮긴다. 문서는 제목 → 리드 → 본문으로 바로 들어간다 (결함 #3-4 해소).
- `.np-outline` 칩 클라우드(20개 2줄) → **수직 목차 레일**.
  `IntersectionObserver`로 현재 읽는 섹션을 표시한다.
- 트리 사이드바: 도메인 = 작은 대문자 섹션 레이블, 개념 = 행,
  하위개념 = 들여쓰기 + 저채도. 위계 리듬을 만든다.

### D. Mermaid 렌더러 — `src/components/Mermaid.tsx`

- `await import('mermaid')`로 **지연 로딩**. mermaid 펜스가 없으면 로드하지 않는다.
- `mermaid.initialize({ theme: 'base', themeVariables })` — `themeVariables`는
  `tokensOf(themeId)`에서 생성. 테마 전환 시 재렌더.
- `react-markdown`의 `pre` 컴포넌트를 오버라이드해 자식이 `language-mermaid`면
  `<Mermaid>`로 교체(중첩 `<pre>` 방지).
- 파싱 실패 시 **원본 소스를 `<pre>`로 폴백** + 조용한 실패 안내. 노트가 빈 칸이
  되는 일은 없어야 한다.
- jsdom 테스트에서 로드되지 않도록 지연 임포트를 유지한다.

### E. 노트 콘텐츠 변환 — 107개

정보를 하나도 잃지 않는다. **표현만 바꾼다.** 노트가 이 프로젝트의 제품이다.
우선순위: 사용자가 지목한 `os-core` 프로세스/스레드 → 각 노트의
`## N. 다이어그램` 표준 섹션 → 상태 기계 → 나머지.

## 검증

- `npx vitest run` — 기준선 **58 파일 / 536 테스트 통과** 유지
- `npm run build` — 타입 검사는 이것만 게이트다 (`tsc -b && vite build`).
  `npx tsc --noEmit`은 파일 0개를 검사하고 항상 성공한다.
- Playwright로 실제 브라우저 확인: `/graph` 우상단 노드 비가림 · 읽기 화면 측정폭 ·
  Mermaid 렌더 · 콘솔 에러 0 · 테마 6종 전환

## 사용자 부재 중 내가 대신 내린 결정

사용자가 "mostly I will follow your rec"로 승인하고 취침했다. 갈래가 있던
지점은 다음과 같이 정했다. 아침에 거부 가능.

1. **레이아웃 = 트리 + 중앙 문서 + 우측 목차 레일**(3열). Bear식 3-pane(도메인 →
   개념 목록 → 문서)은 이 앱의 정체성인 "전체 지도 한눈에 보기"를 잃는다.
2. **하단 떠 있는 pill 제거, 좌측 아이콘 레일로 이동.** 모바일만 하단 탭 바.
3. **측정폭 40em.** Bear는 ~36em이지만 한글 + 코드/표 혼재라 조금 넓게 잡는다.
4. **Mermaid를 강제하지 않는다.** 피라미드·바이트 레이아웃은 Mermaid가 더 나쁘다.
   전용 figure로 처리한다.
5. **다크 기본 + 테마 6종 유지.** Bear 참고는 타이포그래피/여백 기준이지
   팔레트 교체 요청이 아니라고 읽었다.
6. **전역 `index.css` 요소 규칙은 남긴다.** `HomeView`/`GuideView` 등이 의존하고
   있어 걷어내면 개편이 아니라 회귀가 된다. `.prose`가 스스로 리셋한다.
