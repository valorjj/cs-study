# 내 이력 → 개념 지도: UI (2026-08-06)

`docs/superpowers/plans/2026-08-06-resume-concept-map-ui.md` 실행. 태스크 9개
(1·2·3·4·5·5b·6·7·8), 리뷰 사이클 총 17회, 커밋 28개. 536 테스트 통과.

엔진(금고·마스킹·개념매칭·숙련도·방사형·Edge Function)은 앞선 플랜에서 이미 `main` 에 있다.
이 브랜치는 **화면 + store 계약 수정 하나**다.

## 화면 흐름

```
내 이력 탭 (#/resume)
  └ status: none    → VaultGate: 패스프레이즈 최초 설정 (복구 불가 고지)
    status: locked  → VaultGate: 잠금해제
    status: unlocked
       ├ 프로젝트 목록 [편집] [삭제] [마스킹] [개념 지도]
       ├ ProjectForm   등록·편집 (칩·단계 체크박스·서술문) → 저장 시 로컬 매칭
       ├ MaskPanel     후보별 가리기/남기기 + 전송 전문 미리보기 + AI 개념 추출
       └ ConceptMapModal  방사형 지도 → 개념 클릭 → 노트로 이동
       [잠그기] [평문 JSON 내보내기]
```

## 반드시 지켜야 하는 것

- **`activeProjectId` 는 `graphStore`**(라우트 상태, URL에 실림), **`mapOpen` 은 `resumeStore`**
  (세션 UI 위치). 라우트 상태를 `resumeStore` 에 두면 `useUrlSync` 가 두 store를 구독해야
  하고, 그 콜백이 양쪽 합성값을 읽는 순간 히스토리 loop guard가 무효화된다
  (`history.length` 1→3 으로 실증됨).
- **`hydrate()` 는 `status === 'unlocked'` 면 아무것도 하지 않는다.** 없으면 노트 하나 볼
  때마다 금고가 다시 잠기고 패스프레이즈 재입력 + 200k PBKDF2가 돈다.
- **부모(`ResumeView`)는 자식에게 프로젝트 **객체**를 넘기지 않는다. id만 들고 매 렌더마다
  `projects` 에서 다시 찾는다.** 객체를 얼려 넘기면 await를 가로질러 낡은 값이 저장된다 —
  이 브랜치에서 같은 결함이 **네 번** 나왔다.
- **`await` 뒤에는 store를 다시 읽는다.** `MaskPanel.persist`·`runExtract`,
  `ProjectForm.submit` 모두 그렇게 한다. 네트워크 대기 창 동안 삭제·편집이 도달 가능하다.
- **`upsertProject` 는 throw하지 않는다.** `PersistResult` 를 반환하고 `reason` 으로
  잠긴-금고 거부와 디스크 실패를 구별한다. `void` 로 버리면 실패가 침묵한다.
  쓰기 실패 시 메모리는 **유지**하고 실패를 알린다 — 손으로 쓴 이력서는 사라지는 것이
  어긋나 있는 것보다 나쁘다. 그래서 실패 배너는 사용자가 지우거나 다음 저장이 성공할
  때까지 남아야 한다.
- **마스킹 토큰 문자열을 절대 영속화하지 않는다.** `dictOf` 는 결정 순서대로 종류별 번호를
  매기므로 되돌리기 한 번이면 `[COMPANY_1]` 이 다른 용어를 뜻한다. LLM 이유 텍스트에서
  토큰을 걷어내고 저장한다 — 프롬프트가 모델에게 토큰을 그대로 두라고 지시하므로 이유
  문장에 토큰이 들어오는 것은 예외가 아니라 기대되는 형태다.
- **`전송 전문 미리보기` 는 `buildExtractPayload` 의 결과를 그대로 렌더한다.** 별도로
  문자열을 조립하면 언젠가 전송 경로와 갈라진다. `stack` 과 `lifecycle` 은 설계상
  마스킹하지 않고 그대로 전송되므로 **개수가 아니라 값**을 보여준다.
- **개념 클릭은 `openNote(nodeId)` **만** 부른다.** `mapOpen: false` 를 함께 부르면 돌아왔을
  때 지도가 닫혀 있다. "뷰가 바뀌어 안 보인다"와 "사용자가 닫았다"는 다른 사건이다.

## 다음에 안 밟을 함정

**같은 결함이 반복된 세 부류.** 이 브랜치의 결함 대부분이 셋 중 하나였다.

1. **await를 가로지르는 낡은 스냅샷** — 4회. 매번 "같은 파일 안에 옳은 패턴이 이미
   있는데" 새 함수가 그것을 따르지 않았다. 마지막 것은 태스크 리뷰 8회를 통과했다.
   어느 리뷰도 그 이음새(부모→자식 prop)를 소유하지 않았기 때문이다.
2. **코드가 강제하지 않는 것을 주석이 단언** — 앞선 플랜에서 9회, 이 플랜에서도 반복.
   `"반환값을 실제로 읽는다"`(읽지 않았다), `"미리보기가 곧 전송문"`(개수만 보여줬다),
   `"재사용하지 않는다"`(배열을 참조로 공유했다). **주석에 "우회 불가"를 쓰기 전에
   우회를 시도하라.** 뚫리는 방어는 고치지 말고 없애라 — 남겨두면 다음 사람이 믿는다.
3. **어떤 구현에서도 통과하는 단정** — 6회. 두 번은 그 패턴을 없애려던 수정 안에서.
   가장 값진 검증 기법은 **mutation**: 방금 넣은 가드를 지우고 테스트가 죽는지 본다.
   죽지 않으면 그 테스트는 없는 것과 같다. 리뷰어에게 "소스만 읽고 추론하지 말고
   실행해 확인하라"고 지시하는 것이 값을 냈다.

**컴포넌트를 스탠드얼론으로만 테스트하면 이음새를 못 본다.** 실제 도달 불가한 상태를
단정하던 테스트가 두 건 있었다(잠그면 폼이 unmount되는데 필드 보존을 단정). 진입점을
클릭하는 조합 테스트가 결국 결함을 잡았다.

**테스트 픽스처의 가짜 값이 실패 경로를 숨긴다.** `key: {} as CryptoKey` 때문에
`sealJson` 이 `localStorage` 에 닿기 전에 throw했고, 그 파일 8개 테스트가 저장이 아예
동작하지 않아도 통과하는 상태였다.

## 알려진 한계 (병합 시점)

- **클라우드 동기화가 없다.** 이 브랜치는 단일 기기 + `localStorage` 로 완결된다.
  사용자 요구였던 "어디서든 재개"는 아직 충족되지 않았다 — 남은 절반이다.
  전제조건: `docs/worklog/2026-08-05-resume-concept-map-core.md` 의 SQL 배포 검증 3종.
- 마스킹 후보 자동 탐지는 한국어에 근본적으로 약하다. 한글 회사명·사내 코드명은 대문자
  같은 표기 신호가 없다. 안전은 탐지가 아니라 **미리보기 + 명시적 전송 버튼**에 걸려 있다.
- 코드명 후보는 2회 이상 등장해야 제안된다. 한 번만 언급된 이름은 제안되지 않는다.
- `dictOf` 는 `neverMask` 를 다시 확인하지 않는다. 노드가 나중에 생겨 낡은 `mask:true`
  결정이 남으면 기술 용어를 가려 신호를 죽이거나 추출이 차단된다(오류가 위치를 짚어주고
  사용자가 결정을 되돌릴 수 있다).
- `applyMask` 가 대소문자를 무시하므로, 짧은 키가 긴 키가 삽입한 플레이스홀더 토큰을
  먹을 수 있다(`[SYSTEM_1]` → `[[COMPANY_1]_1]`). 평문은 남지 않고 미리보기에서 보인다.
- 좁은 화면에서 개념 지도는 900px 캔버스를 스크롤한다. 반응형은 다음 이터레이션.
