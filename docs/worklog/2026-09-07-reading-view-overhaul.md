# 읽기 화면 전면 개편 — 무엇이 실제 결함이었나

날짜: 2026-09-07 (일요일 야간 자율 작업)
브랜치: `feat/reading-view-overhaul` (main 미병합)
스펙: `docs/superpowers/specs/2026-09-06-reading-view-overhaul-design.md`

사용자가 세 가지를 보고했다: `/graph`에서 로그인 버튼이 컴포넌트를 가림 /
다이어그램을 Mermaid로 / 가독성 대폭 개선(참고: Bear). 그리고 취침했다.

## 세 리포트가 실은 두 개의 원인이었다

### 원인 1 — 앱에 레이아웃 프레임이 없었다

`SearchBar` · `AuthButton` · `ThemeSwitcher` · `ViewToggle` 네 개가 각자
`position: fixed`로 `100vw × 100vh` 캔버스 **위에** 떠 있었다. 여백을 예약해
주는 주체가 없으니:

- 그래프 노드가 로그인 pill 뒤로 들어가 **클릭까지 막혔다** (리포트 #1)
- 하단 `ViewToggle`이 본문 마지막 줄을 덮었다 (가독성 결함)
- 뷰 6개가 `padding-top: 60px`으로 상단 바 높이를 **각자 추측**했다

`AppShell`을 CSS 그리드로 도입해 크롬을 실제 레이아웃 트랙으로 만들었다.
캔버스 원점이 정확히 `(레일 60px, 상단바 54px)`이고 크롬 ∩ 캔버스 = `0px²`임을
Playwright로 확인했다 — fitView·줌·팬 어떤 상태에서도 성립한다.
**겹침을 고친 것이 아니라 도달 불가능하게 만들었다.**

### 원인 2 — 타이포그래피 시스템이 없었다

측정한 결함:

| 결함 | 이전 | 이후 |
|------|------|------|
| 측정폭 | 무제한 → 2000px 화면에서 **한글 90자/줄** | 680px = **한글 46자/줄**(실측) |
| 위계 | 본문 18px인데 h2 17px, h3 15px (**역전**) | 본문 17 / h2 23 / h3 19 / 제목 34 |
| 문단 간격 | 전역 `p{margin:0}`이 노트까지 적용 → **0** | 20px |
| 본문 시작까지 | 크롬 5단 ≈ **250px** | 0 (제목 → 리드 → 본문) |
| 표·코드 | 본문보다 작음(13px) + 셀 테두리 격자 | 15.5 / 13.5px, 헤더 규칙 + hairline |

섹션 칩 클라우드(`flex-wrap` 20개 → 2줄)를 **수직 목차 레일 + 현재 위치
표시**로 바꾸고, 키워드·연결된 개념·읽음 표시도 레일로 옮겼다.

## ASCII 다이어그램은 이미 고장나 있었다

한글은 전각(2셀), 라틴은 반각(1셀)이다. 박스를 반각 기준으로 그렸으므로
**한글이 섞인 모든 박스는 열 정렬이 무너진다.** 미관 문제가 아니었다.

펜스 302개를 분류해 107개가 ASCII 다이어그램이었고, 전량 처리했다.
결과: **태그 없는 펜스 0개** (mermaid 140 · text 28 · 나머지는 코드 언어).

### 전부 Mermaid로 밀지 않았다

| 원래 형태 | 옮긴 곳 | 이유 |
|-----------|---------|------|
| 파이프라인 타이밍(F D E M W), MESI 상태, Ethernet 프레임, JWT 3분할 | **표** | "사이클 × 명령어" 같은 격자·바이트 레이아웃은 표가 정확하다 |
| Big-O 증가율 곡선 | **표**(n=10/100/1000/10⁶ 연산 횟수) | xychart로 5개 계열을 겹치면 mermaid에 **범례가 없어** 어느 선이 무엇인지 알 수 없다. 면접에서 쓸모 있는 쪽은 숫자다 |
| 비유 블록 다수(Collections/List/Set/Queue, HashMap) | **표** | 실은 3~4행 비교표였다 |
| `.dockerignore` 내용, `docker`/`jps` 명령, HPA 공식 | ` ```gitignore ` / ` ```bash ` / ` ```text ` | 애초에 다이어그램이 아니었다 |
| 주소창 입력 8단계, Outbox 3단계, 프로브 함정 3가지 | 마크다운 목록 / 소제목 구조 | 이미 목록이거나 서술이었다 |
| 비트 단위 spread, 병합·퀵 분할, ArrayDeque 원형 배열 | ` ```text ` 유지 | **한글이 정렬 영역에 없는 순수 ASCII**. 전각 문제가 없고, 비트 자리는 오히려 정렬이 의미다 |

Mermaid로 간 것: 프로토콜 왕복 → `sequenceDiagram`(TCP 상태 전이는
`Note over`로 양쪽 상태를 메시지에 붙임), 상태 기계 → `stateDiagram-v2`,
**cwnd 톱니 → `xychart-beta`**(실제 차트 타입이 있다), 계층·포함 구조 →
중첩 `subgraph`.

### 이 판단을 검사로 고정했다

`interview-map/scripts/check-mermaid.mjs` — 노트의 모든 mermaid 블록을 실제
mermaid 빌드로 렌더해 실패를 잡는다. **앱은 파싱 실패 시 원본 소스로
폴백하므로 깨진 다이어그램이 "의도한 코드 블록"처럼 보이며 리뷰를 통과할 수
있다.** 그래서 게이트가 필요했다. `--sheet`로 컨택트 시트도 낸다.

한글 뒤에 정렬용 박스 문자가 오는 `text` 블록은 0개여야 한다는 검사도 돌렸고,
**이 검사로 내가 새로 쓴 슬라이딩 윈도 블록이 바로 그 결함을 갖고 있는 것을
발견**해(라벨을 박스 안에 넣었다) 순수 ASCII 격자 + 마크다운 범례로 고쳤다.

## 곁에서 발견한 기존 버그 — 테마가 새로고침마다 초기화

Terminal을 골라도 새로고침하면 Midnight으로 돌아가고, **저장값까지 기본값으로
덮여** 있었다. `useThemeEffect`의 두 이펙트가 같은 커밋에서 도는 순서 때문:

```
① hydrate: localStorage에서 'terminal' 읽어 setTheme('terminal')
② persist: 아직 하이드레이션 전 기본값 'midnight'을 들고 실행 → 저장값 덮음
   StrictMode 2차 패스에서 ①이 덮인 'midnight'을 읽는다 → 소실
```

`ref` 플래그로는 못 막는다(①이 ②보다 먼저 돌므로 플래그는 이미 서 있고,
StrictMode 재실행은 상태 업데이트 반영 전에 일어난다). `graphStore`가
`PROGRESS_KEY`에 이미 쓰던 방법 — **스토어 생성 시 동기 읽기** — 을 적용했다.
그 파일 주석이 정확히 이 레이스를 두고 `"StrictMode's double-mount would
otherwise clobber"`라고 경고하는데, 테마만 그 처리를 못 받고 있었다.

## 대신 내린 결정 (아침에 거부 가능)

1. **레이아웃 = 트리 + 중앙 문서 + 우측 목차 레일**(3열). Bear식 3-pane은 이
   앱의 정체성인 "전체 지도 한눈에 보기"를 잃는다.
2. **하단 떠 있는 pill 제거 → 좌측 아이콘 레일.** 모바일만 하단 탭 바(그리드 행).
3. **측정폭 680px.** Bear는 ~620px이지만 한글 + 코드/표 혼재라 조금 넓게.
4. **다크 기본 + 테마 6종 유지.** Bear 참고는 타이포/여백 기준으로 읽었고
   팔레트 교체 요청으로는 읽지 않았다.
5. **전역 `index.css` 요소 규칙 유지.** `HomeView`/`GuideView`가 의존하므로
   걷어내면 개편이 아니라 회귀다. `.prose`가 스스로 리셋한다.
6. **`playwright`를 devDependency로 추가.** 다이어그램 검사가 브라우저를
   필요로 하고, 이 프로젝트의 검증 도구가 원래 Playwright다.
7. **퀴즈/드릴/리뷰 답안은 `.prose` 적용 범위에서 제외.** 리포트 #3의 대상이
   아니고, 각자 카드 레이아웃이 있어 건드리면 범위가 번진다.

## 검증

- `node interview-map/scripts/check-mermaid.mjs` → **140/140 렌더**
- `npx vitest run` → **61 파일 / 554 테스트 통과** (기준선 536 + 신규 18)
- `npm run build` 통과 — 타입 검사는 이것만 게이트다
- 실제 브라우저: 노트 20종 × 다이어그램 43개 렌더, 콘솔 에러 0,
  가로 오버플로 0, SVG 컨테이너 이탈 0
- **테마 6종 전부** mermaid 재렌더 확인, 라벨/노드 대비 **7.09~13.06**
  (WCAG AAA = 7). Terminal(녹색 단색) 테마는 mermaid 기본 팔레트로는 판독
  불가였으므로 `themeVariables` 주입이 필수였음이 확인됐다
- 뷰 7종 × 1440 / 1200 / 414px 콘솔 에러 0

## 안 한 것

- **main 병합·푸시를 하지 않았다.** 공개 저장소 + Vercel 자동 배포라
  전면 UI 개편을 확인 없이 라이브로 올리는 것은 되돌리기 어렵다.
  `git merge --ff-only feat/reading-view-overhaul` 한 줄로 끝난다.
- mermaid 번들(gzip ~700KB)은 동적 import로 분리했으나, 다이어그램이 많은
  노트에서 첫 렌더까지 스켈레톤이 잠깐 보인다. 프리페치는 넣지 않았다.
